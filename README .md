## Description

School Management System is a command-line program, written entirely in Python, that lets a user manage multiple schools, enroll students into them, and record and average each student's grades across different subjects. It was built as my final project for CS50P, and it also served as the final project for a Python bootcamp I am enrolled in, so the design had to satisfy both a menu-driven CLI specification and CS50P's requirement of testable, top-level functions.

The program is a single file, `project.py`, run from the terminal with `python project.py`. When it starts, it shows a main menu with three options: manage schools, manage students, or exit. Choosing "School inputs" opens a submenu where the user can create a new school, list every school that has been created so far, register a new student in a chosen school, or view all the students currently enrolled in a chosen school. Choosing "Student inputs" opens a second submenu where the user can add a grade for a subject to a student, view all of a student's grades, or view a student's average grade. Each submenu is shown once per visit and then returns control to the main menu, which is the only part of the program that loops, using a `while True` loop inside `main()`.

**Classes.** The program uses three classes to model the data, and the second one demonstrates inheritance. `Student` is the base class and only stores a name and an age. `StudentGrades` inherits from `Student`; instead of repeating the name/age logic, its `__init__` takes an already-built `Student` object and calls `super().__init__()` with its name and age, then adds an empty `grades` list of its own. This is the class actually stored inside a school once a student is registered, because it is the one capable of holding and reporting grades. `School` is independent; it stores a name, a type (1 for Primary, 2 for Secondary, 3 for Both), and the list of students enrolled in it, and it rejects a new student if the name already exists in that school.

**Testable functions.** CS50P requires at least three additional functions, beyond `main()`, that live at the top level of `project.py` (not nested inside a class) and can be tested independently with `pytest`. I pulled the four pieces of logic in the program that don't depend on user input or printed output into their own functions so they could be tested directly: `calculate_average(grades)` computes the average of a list of grade dictionaries and returns 0 if the list is empty, avoiding a division-by-zero crash; `is_duplicate_subject(grades, name)` checks whether a subject has already been recorded for a student; `get_school_type_name(type_number)` maps a school's numeric type to its readable name using a dictionary instead of a long if/elif chain; and `parse_number(text)` converts a string to an integer or returns `None` if the string isn't a valid whole number. The class methods call these functions internally instead of duplicating their logic, and `test_project.py` contains one test function per helper (`test_calculate_average`, `test_is_duplicate_subject`, `test_get_school_type_name`, `test_parse_number`), each checking a normal case, an edge case, and an invalid case.

**Handling bad input.** Every place the program reads a number goes through `get_number()`, which uses `parse_number()` to validate the text and returns `None` on invalid input instead of crashing; every caller checks for `None` before continuing, so a stray letter anywhere in the program just prints a short error and returns to the previous menu rather than raising an exception. To run the tests: `pytest test_project.py`.
